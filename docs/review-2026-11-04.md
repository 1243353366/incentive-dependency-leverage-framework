# Review, 2026-11-04

Method: static reading of `app.js`, `index.html`, `framework-data.js`, plus greps for
rendering, dynamic evaluation, storage and external loads. Then the new test suite.

Available: source reading, static analysis, data invariant checks.
Not available this pass: executing the app in a browser, click-path testing, fuzzing, and any
dynamic analysis. Absence of a finding below does not mean absence of a defect.

## Findings

1. **No Content-Security-Policy (fixed).** `index.html` loaded two local scripts and set no
   policy, so any markup that ever reached the DOM would run with the page's authority. A
   meta CSP now restricts scripts to this origin, blocks inline script, and pins `base-uri`
   and `form-action`. `frame-ancestors` cannot be expressed in a meta tag, so clickjacking
   remains unaddressed until hosting sets a header; recorded in `LIVING.md`.
2. **Escaping is correct but unguarded (guarded).** User text is escaped where it is echoed
   (`valOf('situation')`, `valOf('mirror')` both pass through `esc()`), and the renderer
   escapes framework strings. Nothing enforced that, so a future interpolation could skip it
   silently. Tests now assert the two user-facing echoes use `esc()`, and `make audit` lists
   every unwrapped interpolation for a human to read.
3. **Sessions have no lifecycle (open).** `localStorage` holds every session under one key,
   with no version, expiry or clear control. For a tool whose input is someone's most
   difficult personal situation, that is the largest privacy gap in the repo. Not fixed here
   because it changes the interface; recorded as an open decision with the options.
4. **No dynamic evaluation (checked, clean).** No `eval`, no `new Function`, no `innerHTML`
   fed by a string that has not passed an escape helper.
5. **No third party code (checked, clean).** All scripts are same-origin; there is no CDN, so
   there is no supply chain to pin.
6. **No test executed the app (gap, partially closed).** The suite covers data and source
   hygiene only. The coach's runtime behaviour on a real decision path is unverified by
   machine, and that is stated rather than glossed in `LIVING.md`.

## Addendum, same day: finding 3 closed

Retention was the gap worth closing first, because it was the only one where the harm lands on
the person using the tool rather than on the tool.

Fixed: versioned key, `updated_at` stamped on save, 90 day prune on load and save, one clear
control, and a one-time migration off the old key. The retention sentence shown in the
interface is generated from the enforced constant, so the promise and the rule cannot drift
apart in a later edit.

Still open, and deliberately:
- pruning only runs when the page opens, so an abandoned browser keeps its copy;
- clickjacking needs a hosting header, and a JavaScript frame-buster is not a substitute;
- nothing here executes the app, so the coach's runtime behaviour remains unverified by
  machine.
